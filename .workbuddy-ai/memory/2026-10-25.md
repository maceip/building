**TWO HARD-WON LESSONS (both cost real debugging time):**
1. **`Modifier.weight(0f)` THROWS** `IllegalArgumentException: invalid weight; must be greater than zero`. Animating a weight to exactly 0 crashes when the animation completes — the app would have crashed on every real phone expansion. Floor it (0.0001f, same epsilon as the existing `Spacer(Modifier.weight(0.0001f))` in WideProjectsHome). The crash surfaced as `UncaughtExceptionsBeforeTest` polluting an unrelated ScreenStateTest — cross-test pollution was the symptom, the weight was the disease.
2. **`ImageComposeScene.render(nanos)` takes an ABSOLUTE frame timestamp.** Restarting the clock mid-test (e.g. rendering 50ms after the initial loop already reached 1500ms) silently stalls ALL animations — layouts freeze mid-state with no error. Keep a running `now` variable. Also: the first render after a state change only *schedules* animations; the value applies on the frame after the animation's first callback, so mid-transition captures need 2–3 tick frames first.
